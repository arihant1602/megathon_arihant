On-device classifier: model comparison

Liquid neural networks (CfC) vs small transformers (Ettin) for the incident-report classifier · measured on a Qualcomm SM8750P dev kit (Snapdragon 8 Elite) · QAIRT/SNPE 2.47 · 10 Oct 2026
Recommendation: Ettin-encoder-17m with a trimmed 8k vocabulary It is the same size as the best LNN (6.0 MB vs 5.5 MB int8), equal or faster on every processor, the only family that passes the 200 ms line on CPU, loads 5–18× faster, and starts with pretrained English knowledge. The LNN would have to learn the language from ~1,300 conversations. The LNN showed no speed or size advantage.

Findings

Speed

  • NPU: every model takes 0.7–2.5 ms. Speed cannot choose between them on the Hexagon HTP.
  • GPU: all pass (5.6–44 ms); Ettin is 2–5× faster than the LNNs.
  • CPU: the LNNs fail (334–353 ms at 128 tokens, ~1.45 s at 256). Ettin-17m passes at 8–15 ms, Ettin-32m at 21–40 ms. The LNN has to be unrolled into a fixed graph of 5,600–11,300 tiny sequential ops, and the CPU runtime pays overhead for each. A transformer is 325–457 large, parallel ops.
  • Hidden size barely matters for the LNN (h64 vs h192: 334 vs 353 ms CPU), so per-op overhead, not maths, dominates.

Size and load time

  • The embedding table dominates: LNN h192 is 5.5 MB with an 8k vocab and 15.8 MB with the full 50k vocab.
  • Same 8k vocab: Ettin-17m 6.0 MB vs LNN 5.1–5.5 MB int8 — effectively equal.
  • The LNN's file grows with input length (5 → 8 MB from 128 → 256 tokens) because of unrolling; Ettin's does not.
  • First load on the NPU: LNN 1.7–6.0 s, Ettin 0.3–0.8 s.

Input length

The existing labelled conversations are 43 tokens (median) and 71 tokens at most, so a 128-token input covers them all. 256 only matters if the new multi-turn data runs much longer.

Method

  • Device: Qualcomm dev kit "Sun", SoC SM8750P (Snapdragon 8 Elite), Hexagon v79 HTP, Android 15. The Snapdragon 695 test phone was not benchmarked.
  • Pipeline: PyTorch → ONNX (opset 17, static shapes, onnxsim; onnxruntime matched PyTorch within 1.8e-6) → qairt-converter → snpe-dlc-quant (int8) → snpe-net-run with --perf_profile burst --profiling_level basic → snpe-diagview.
  • Inputs: 50 real conversations from data/*.jsonl, tokenized with the Ettin tokenizer, padded to L.
  • Weights are random. Ettin was built from its published config. Speed and size do not depend on weight values.

Limits

  • Times are model execution only: no tokenization or app overhead.
  • Accuracy after int8 quantization is untested; measure it once the model is trained.
  • An LNN written as a plain loop in app code (outside the Qualcomm SDK) might be much faster on CPU. Not measured.
  • NPU load time could drop with an offline-prepared graph cache (snpe-dlc-graph-prepare). Not measured.
  • Trimming Ettin's vocabulary means keeping only the pretrained embedding rows for tokens the form pack uses (plus common English), with an unknown-token fallback.
